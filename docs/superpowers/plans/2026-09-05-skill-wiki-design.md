# 知识点 Wiki（边面边学）设计文档

> **实施状态（2026-09-05）：** 全部完成。迁移 0012 + 18 个知识点骨架种子（facts/金标示例程序化导入，18×4 句手写短句）、四个 API、/skills 列表 + /skills/[id] 详情页、三处入口 + 导航、深讲生成管线（真实生成验证通过，个性化提示引用了用户历史回答）。回归 208 项 pytest + 前端全绿。一处实施偏差：深讲生成复用评估 provider（assessment_model），路由注入相应实例。

> **定位一句话：** 现有系统有"测"（面试）、"评"（盲评分）、"练"（drill）、"验"（延迟验证），唯独缺"学"。本设计补上这一环：遇到不会的知识点，当场就能看到结构化的讲解，并沉淀在数据库里可复用。

**设计原则（ponytail）：**

1. **面试中不开卷。** 答题页面不提供任何资料入口——练习的真实性优先。学习发生在"答完之后"：反馈卡、报告、画像三处入口。这才是"边面边学"的正确含义：每答完一题，立刻能学到它背后的知识点。
2. **内容三层，成本递进：** 程序化骨架（零成本，从现有数据导出）→ 预置精讲（一次性人工内容）→ 按需生成（真实模型调用，结果缓存入库，只花一次钱）。
3. **个性化是差异点：** 同一个知识点，讲解里能带"你上次的回答跳过了什么"——这是通用 wiki 网站做不到的。
4. 不引 Markdown 渲染器、不做富文本编辑器、不做版本历史（YAGNI）。

---

## 一、内容模型（一个知识点页有什么）

每个知识点的 wiki 页由六块组成，全部结构化存储（JSON），前端直接排版：

| 区块 | 内容 | 来源 |
|---|---|---|
| **是什么** | 一句话定义 | 预置手写（每点 1 句） |
| **面试为什么考它** | 考察意图 | 预置手写（每点 1 句） |
| **核心答题要点** | 3-6 条要点 | **程序化导入**：直接复用题库 reference_facts（零手写） |
| **常见误区** | 2-3 条 | 预置手写（每点 2 句）+ 生成时可补充 |
| **面试官会怎么追** | 追问方向 | 程序化导入：题库 signals + 该知识点历史追问记录（InterviewFollowup 已积累） |
| **示例回答** | 3 级 / 4 级各一段 | 程序化导入：金标集标注回答（golden/answers.jsonl 已有 0-4 级样本） |
| **深讲（可选）** | 按需生成的机制详解 + 针对你的薄弱点评 | **模型生成，缓存入库** |
| **我的掌握度** | 当前等级 / 样本数 / 最近轨迹 / 待验证状态 | 已有（knowledge_state） |

关键洞察：**六块里四块不需要写任何新内容**——reference_facts、金标集、追问历史、掌握度全是现有数据。人工只需为 15 个知识点各写 4 句话（是什么/为什么考/2 条误区），半天工作量。

## 二、数据模型（迁移 0012）

```python
class SkillWiki(Base):
    __tablename__ = "skill_wikis"
    skill_id: str  # PK, FK -> skill_catalog.id
    content_json: Text       # 预置骨架 + 生成的深讲，结构化 JSON
    has_deep_dive: bool      # 是否已生成过深讲
    source: str              # "preset" | "generated"
    model_name: str | None
    prompt_version: str | None
    updated_at: datetime

class SkillStudyLog(Base):
    id: str PK
    user_id: str  # FK users
    skill_id: str  # FK skill_catalog
    source: str   # "report" | "profile" | "skills_page" | "post_answer"
    studied_at: datetime
```

- 覆盖式更新（重新生成深讲直接覆盖 content_json 的 deep_dive 节），不做版本历史。
- `skill_study_log` 只做"学过"的流水，掌握度判断仍由画像评分驱动——学过≠会了，避免自我标记污染画像。

## 三、生成管线（深讲）

- **显式触发**：详情页"生成深度讲解"按钮（不自动生成——15 个点全生成是一次不必要的批量支出；用户点到哪个学哪个）。
- **输入**（单次调用，JSON mode，复用项目分析 provider 与主模型）：
  - 知识点 id、名称、signals、reference_facts、相关题目文本（题库）
  - 该用户此知识点最近 1-2 次回答 + 模型点评（个性化素材）
- **输出 JSON**：`{mechanism: "机制详解（300-500字）", why_matters: "...", pitfalls: [...], personal_focus: "针对你上次回答的薄弱提示（100字内）"}`。
- **程序侧校验**：字段存在性 + 长度截断；解析失败重试一次，仍失败报 502（沿用 provider 错误映射）。
- **缓存**：生成结果写 `skill_wikis.content_json.deep_dive`，`has_deep_dive=1`；已有深讲时按钮变"重新生成"。
- **prompt_version** 记录，与评分 prompt 同一套校准规矩。

## 四、API

```
GET  /api/skills                       # 知识库列表：名称/类别/掌握度/是否已学/有无深讲
GET  /api/skills/{skill_id}            # 详情：wiki 各区块 + 掌握度 + 轨迹 + 相关题目 + 我的历史回答链接
POST /api/skills/{skill_id}/wiki/generate   # 生成/重生成深讲（真实模型）
POST /api/skills/{skill_id}/study      # 标记已学（body: {source}）
```

预置骨架在迁移或应用启动时种子化（幂等 upsert，不覆盖已生成的深讲）。

## 五、前端与入口

- **`/skills` 知识库列表页**：按类别分组的卡片（名称、掌握度条、样本数、"未学习"角标）——面试前快速刷一遍的入口。
- **`/skills/[skill_id]` 详情页**：上述八块内容自上而下；顶部就是掌握度条 + "练一次"按钮（直接复用 `/api/practice/drill?skill_id=`，闭环咬合）。
- **三处学习入口**（都是"答完之后"）：
  1. 报告页：每道题的知识点标签 → 可点击跳详情页；"不知道/跳过"的题尤其要给入口；
  2. 画像页：技能卡片（含水平条那块）整体可点击进详情；
  3. 面试完成反馈/练习反馈卡：尾部加"这个知识点的讲解 →"链接。
- 导航栏加"知识库"。

## 六、与现有闭环的咬合

```
答题 → 评分 → 看到薄弱知识点 → [学] wiki 讲解（含个人薄弱提示）
  → [练] 专项 drill（已有）→ [验] 延迟验证（已有）→ 画像升级
```

画像技能卡今后显示"已学/未学"角标（study_log 驱动），薄弱但未学习的排最前——"测练验"之外让"学"有位置。

## 七、明确不做

- 面试答题页内嵌资料（破坏练习真实性）。
- 富文本/Markdown 编辑器、wiki 协作编辑、版本历史。
- 自动批量生成全部深讲（按需生成 + 显式按钮；将来若要预生成，加一个管理脚本即可）。
- 用户自建知识点（知识点必须与题库/画像锚定，自由创建会破坏闭环；有需要时加"申请新知识点"再说）。
