# Echo Offer 面试历史记录设计

## 1. 目标与范围

为本地单用户版本增加面试历史页面，让用户可以长期查看以前的面试、继续未完成的面试、打开已经生成的报告，并对不需要的记录执行单条删除。

本次实现范围：

- 首页顶部增加“面试记录”入口；
- 新增 `/history` 历史页面，按最近面试时间倒序展示；
- 未完成的面试可以继续；
- 已完成且有报告的面试可以查看结果；
- 评分或报告生成失败时保留记录，并允许重新生成；
- 支持删除单条记录，删除前二次确认；
- 列表显示完成题数、评分状态、答得好的地方数量和待补充地方数量；
- 不展示 0～100 总分，不增加搜索、筛选、趋势图和多用户权限。

现有数据库已经保存每场面试的题目、回答、评分批次和报告，因此不新增重复的历史主表。

## 2. 用户体验

### 2.1 入口与页面

首页顶部导航调整为：

```text
准备面试 · 面试记录 · 模型设置
```

页面地址为 `/history`。页面保持当前轻量、留白充足的视觉风格，不使用密集后台表格。首页的分区编号已经说明操作顺序，文案使用直接的名词和动作，不重复写“先做这一步”“随时可以修改”这类流程提示。简历入口使用“上传你的简历”“选择简历文件”，文字区域使用“检查简历内容”。

每条记录是一张卡片，展示：

- 项目名称；
- 面试时间；
- 完成题数，例如 `6 / 8`；
- 当前状态；
- 答得好的地方数量；
- 待补充的地方数量；
- 一个主要操作按钮和一个删除按钮。

### 2.2 状态和操作

状态由面试状态、报告状态和最近一次评分任务状态共同决定：

| 条件 | 页面文案 | 操作 |
| --- | --- | --- |
| 面试未完成 | 进行中 | 继续面试 |
| 面试完成且报告有效 | 已完成 | 查看结果 |
| 已完成但尚无报告 | 报告待生成 | 重新生成 |
| 最近一次评分失败 | 生成失败，可重试 | 重新生成 |
| 没有任何历史 | 还没有面试记录 | 开始第一场 |

“重新生成”进入现有报告页面，继续使用已有的批量评分重试逻辑，不在历史页重复实现评分流程。

加载失败时显示页面内错误提示和“再试一次”；删除失败时保留原卡片并提示原因。删除操作使用确认对话框，避免误操作。

## 3. 数据与持久化

### 3.1 复用现有数据

历史记录以 `interview_sessions` 为主表，通过已有外键关联：

- `resume_projects.project_name`：项目名称；
- `interview_targets`：求职方向和目标岗位；
- `answer_attempts`：回答数量和回答状态；
- `assessment_batches`、`operation_jobs`：评分批次和任务状态；
- `interview_reports`：最新报告及优势、待补充数量。

不把摘要复制成另一套可变数据，列表中的摘要每次从当前关联数据读取，避免历史卡片和报告不一致。

### 3.2 删除语义

使用现有的 `interview_sessions.archived_at` 做软删除：

- 历史列表只返回 `archived_at IS NULL` 的记录；
- 删除后不再出现在历史页面，也不能从页面继续面试或查看；
- 原始回答、评分和用户画像关联暂不物理删除，避免外键断裂；
- 本地 Alpha 暂不提供恢复入口，后续如有隐私清理需求，再单独设计彻底删除。

用户看到的操作仍然叫“删除记录”，不在页面暴露“软删除”等内部术语。

## 4. 接口设计

### 4.1 查询历史

继续使用：

```text
GET /api/interviews/history
```

返回值按 `created_at DESC, session_id DESC` 排序，每项补充项目和摘要字段：

```json
{
  "session_id": "...",
  "status": "in_progress",
  "project_name": "Echo Offer",
  "direction": "agent_application_rag",
  "target_title": "Agent 应用工程师",
  "completed": 6,
  "total": 8,
  "report_status": null,
  "analysis_status": null,
  "strength_count": null,
  "gap_count": null,
  "created_at": "...",
  "updated_at": "..."
}
```

没有报告时 `strength_count` 和 `gap_count` 为 `null`，前端显示“—”，不把缺少报告误认为 0。

### 4.2 删除记录

新增：

```text
DELETE /api/sessions/{session_id}
```

接口只允许操作当前本地用户的面试；找不到记录或记录已经删除时返回 404。成功后设置 `archived_at` 并返回 204。接口不删除回答、报告或画像数据。

### 4.3 复用详情接口

历史页的操作继续复用：

```text
GET /api/sessions/{session_id}
GET /api/sessions/{session_id}/report
```

未完成记录跳转到 `/interview/{session_id}`；已完成记录跳转到 `/report/{session_id}`。报告页已有重新生成入口，历史页不重复调用模型。

## 5. 前端结构

新增 `frontend/app/history/page.tsx`，负责：

1. 加载历史列表；
2. 将后端状态转换为自然中文文案；
3. 根据记录状态显示“继续面试”“查看结果”或“重新生成”；
4. 删除前确认，删除成功后移除对应卡片；
5. 处理加载、空列表、请求失败和删除失败状态。

`frontend/lib/api.ts` 增加历史类型、`getInterviewHistory()` 和 `deleteInterview()`。页面沿用 `mint-shell`、`mint-header`、`mint-card`、`mint-button` 和现有移动端响应式规则，不引入新的 UI 框架。

## 6. 错误处理与边界

- 历史列表请求失败不影响已有面试数据，只显示重试提示；
- 删除请求失败不移除前端卡片；
- 评分失败不改变面试回答和完成状态；
- 未完成面试的完成题数来自回答记录，不根据页面缓存；
- 缺少项目名称时显示“未命名项目”，不阻止查看记录；
- 没有报告时优势和待补充数量显示“—”，不显示为 0；
- 暂不实现分页，单用户 Alpha 先按完整列表读取，记录数量明显增加后再加入分页或游标。

## 7. 测试策略

后端测试：

- 历史列表返回项目名称和报告摘要数量；
- 记录按时间倒序；
- 未完成记录的完成数正确；
- 没有报告时摘要数量为 `null`；
- 删除后记录从历史列表消失；
- 删除不会清除回答、报告和画像关联；
- 不能删除不存在或已归档的记录。

前端测试：

- 首页包含“面试记录”入口和 `/history`；
- 历史页包含状态文案及三个主要动作；
- 空状态、重试和删除确认文案存在；
- 不出现 0～100 总分或内部评估术语；
- 历史页生产构建通过。
